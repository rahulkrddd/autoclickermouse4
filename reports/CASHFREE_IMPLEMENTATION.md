# Cashfree implementation
Cashfree is the default online provider and Razorpay remains available. Provider-specific operations are in `services/payment/`; final paid business effects continue through the existing shared `finalize()` function. New routes: `GET /api/payments/config`, `POST /api/payments/create-order`, `POST /api/payments/verify`, `GET /api/payments/status/:internalOrderId`, and `POST /webhooks/cashfree`. Legacy Razorpay routes remain. Cashfree create-order uses server pricing and returns only session/reference data. Verification fetches Cashfree order and payment attempts and accepts only `SUCCESS`, exact INR and exact amount. Webhooks use the raw body, signature and timestamp before processing. Site-scoped models, deterministic internal IDs and unique compound indexes protect retries. Inventory, customer, coupon and order creation use the existing transaction-backed finalizer.
